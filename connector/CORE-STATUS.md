- `internal/discovery` adds LAN (hand-rolled DNS-SD over multicast, `_nexal._tcp.local.`) and WAN (coordinator rendezvous, `GET /api/peers`) peer *discovery*. It authorizes nothing: `AllowedPeers` is derived from the coordinator's list alone, and a peer seen only over mDNS never enters it. Both mechanisms are gated off by default (`SharingPolicy`), so nothing is announced or polled until a caller opts in — whether resource sharing should default on is an unresolved product decision and is not decided in code. The decoder is fuzzed against truncated, malformed and self-referential packets; NAT traversal (ICE) is not implemented and no code path relays bytes. The peer transport has not run between two real Macs on a real LAN.
- `internal/discovery` is now wired into the agent lifecycle, and `client.Advertise` (`POST /api/peers/advertise`) exists, so the coordinator's `host_addresses` table can finally populate: before this, the directory always returned peers with empty address lists because nothing ever published an address. `Agent.Run` starts one discovery goroutine that advertises on start and republishes on an interval (5 min, 45 s after a failure), polls the peer directory through `discovery.Rendezvous`, and merges mDNS candidates for display, locality and dial addresses only. `AllowedPeers` still comes from the coordinator's list alone; `TestAgentMDNSOnlyPeerNeverEntersAllowedPeers` asserts it at the wiring layer, alongside the existing package-level test. All of it is off unless the owner adds a `discovery` block to the config (`lanDiscovery`, `wanRendezvous`, `deviceFingerprint`, `peerPort`); the block is absent by default, absent means off, a gate opened without a fingerprint or port is refused rather than silently ignored, and `resourceSharing` is deliberately not configurable (§36.4 is unresolved).
- The advertise/directory contract is tested against the coordinator's LITERAL response bodies, and `TestHonestyStringsAndCapsMatchCoordinatorSource` reads `apps/coordinator/src/peers.ts` itself (skipped when the platform repo is not checked out alongside) so `MAX_LAN_ADDRESSES`, `MAX_WAN_ADDRESSES`, `MAX_PEERS` and the three honesty strings cannot drift silently again — HARDENING-PLAN §43. Both exact strings are now accepted and nothing else is.
