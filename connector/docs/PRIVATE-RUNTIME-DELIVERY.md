# Connected-only private inference runtime

Distributed inference is off until this connector is enrolled, locally connected to the neXal mesh, and authorized by the coordinator for an assigned private runtime. Signing into the app or reaching a LAN is not sufficient. A fresh server-side tunnel report, active host/network, nonexpired credentials and matching tenant/network assignment are required for runtime delivery. The inference API also checks the requesting connector and every configured worker remain in the same active network.

The public connector includes generic lifecycle, HTTPS, signature/hash verification and process-supervision code only. Proprietary inference implementation, model artifacts and private configurations belong in `nexal-platform`'s private release pipeline. The developer MLX harness in `runtimes/` is public integration/test scaffolding, not a bundled private engine or a distribution channel for secret weights/keys. The app packager rejects common runtime/weight/key payload files.

`internal/privateruntime` obtains a new signed manifest from the configured coordinator for every execution session, fetches every file through host-authenticated coordinator routes, and verifies the signature and SHA-256 digests before execution. There is no reuse of a payload cached from an earlier connection or execution. The public verification key is selected by the coordinator and received through its authenticated HTTPS connection; arbitrary callers cannot choose the trusted signer.

Payloads live in an owner-only `runtime-sessions/session-*` directory beside the connector configuration. The fixed signed executable `runtime` receives only `--session-file <path>` and a minimal environment. It does not inherit the connector host token, signing secrets or provider API keys. Its working directory contains its own freshly downloaded artifacts. Server/provider/master signing and encryption keys must never be published in those artifacts; only narrowly scoped runtime credentials may be issued when necessary.

The supervisor checks local connectivity and lease expiration every two seconds, renews authorization every ten seconds, stops on pause/resource withholding/active conflicting jobs, kills the process group and removes its session directory on termination. A private-runtime lease watchdog additionally exits orphaned processes. Startup under an exclusive local lock removes abandoned payload directories. Process crashes and secure deletion from backups/swap are not equivalent to normal cleanup; no secure-erasure guarantee is made.

The coordinator stores only runtime session metadata in migration `0057_inference_runtime_sessions.sql`. It serves assigned private artifacts from R2 with no-store responses and checks connectivity/authorization again for each file and renewal. Lease replacement, expiration, membership loss, revocation and deployment reassignment invalidate continued access. Reports are authenticated connector observations, not hardware attestation.

Private code downloaded to a customer-controlled computer remains inspectable by that computer's owner. Runtime delivery is an access/lifecycle boundary, not DRM. Host/device credentials needed to authenticate the connector are obtained through enrollment and local secure storage; removing embedded service secrets does not eliminate authentication.

No production bundle is manufactured by the connector. Publish and provision the approved private runtime using the platform's `services/distributed-inference` tooling. Until an assignment exists, the bootstrap remains inactive and retries without shipping an embedded fallback engine.

A legacy tracked base64 PKCS#12 container with an encrypted private-key bag was removed from the working tree during this change and preserved outside the repository in a restricted local backup. Git history is unchanged. If that signing identity was shared/pushed, rotate it and plan history cleanup separately; do not make it a downloadable runtime credential.
